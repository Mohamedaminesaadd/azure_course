Your Python program **doesn't store the data permanently itself**.

Its job is:

```text

   ↓

```

Azure Event Hubs is the event streaming platform:

```text
Python Producer
       │
       │
       ▼
┌─────────────────────┐
│   Azure Event Hubs  │
│                     │
│ Event 1             │
│ Event 2             │
│ Event 3             │
│ Event 4             │
│ ...                 │
└─────────────────────┘
       │
       ▼
    Consumer
```

The consumer then reads those events.

### Event Hubs does not automatically mean "analyze everything every time."

The producer only produces events.

```text

Event 3 → process
```

and maintain a checkpoint.

Later it continues from:

```text

```

rather than necessarily starting from Event 1 again.

That's why your **checkpointing** work with Blob Storage is important.

```text
       │
```

The consumer then reads those events.

# 37. One subtle problem with your simulation

There is one thing I would change if you want this to represent a realistic taxi system.

Currently you generate:

```python
speed = random.uniform(20, 60)
heading = random.randint(0, 359)
```

independently.

And you generate:

```python

longitude += random.uniform(...)
```

independently.

That means the taxi can theoretically say:

```text

speed = 50 km/h
```

but move slightly southwest.

A real GPS device wouldn't behave like that.

For a **learning/demo pipeline**, your current code is completely fine.

For a more realistic simulation, we could make:

```text
speed + heading
       │
       ▼
calculate movement
       │
       ▼
new latitude/longitude
```

So the taxi actually moves in the direction indicated by its heading.

That would make your Event Hubs → Data Lake → Processing → Analytics project much closer to a real-world IoT/transportation pipeline.

Yes. This is the **next stage of your pipeline**: it takes the data you already stored in **ADLS `/raw`**, validates and cleans it, then saves the result in **ADLS `/processed`**.

# 12. Why can't we simply subtract latitude?

You cannot simply do:

```python
lat2 - lat1
```

and call that kilometers.

GPS coordinates are based on the Earth.

So your code uses the **Haversine formula**.

You define:

```python
R = 6371.0
```

which represents the Earth's approximate radius in kilometers.

---

# 13. Convert degrees to radians

You do:

```python
lat1 = math.radians(lat1)
lat2 = math.radians(lat2)
```

and:

```python
delta_lat = math.radians(
    lat2 - lat1
)
```

and:

```python
delta_lon = math.radians(
    lon2 - lon1
)
```

This is necessary because Python's trigonometric functions such as:

```python
math.sin()
math.cos()
```

work with radians.

---

# 14. Haversine calculation

Then:

```python
a = (
    math.sin(delta_lat / 2) ** 2
    +
    math.cos(lat1)
    *
    math.cos(lat2)
    *
    math.sin(delta_lon / 2) ** 2
)
```

and:

```python
c = 2 * math.atan2(
    math.sqrt(a),
    math.sqrt(1 - a)
)
```

Finally:

```python
return R * c
```

So:

```text
GPS point A
     +
GPS point B
     ↓
Haversine formula
     ↓
distance in km
```

```text
         │ d1
         ▼
      Event 2
         │
         │ d2
         ▼

```

It calculates the distance along the recorded GPS trajectory.

# 41. But there is one VERY important thing about this code

Just like your previous processing script, this analysis script is currently **batch-based**.

When you run:

```bash
python analyze_data.py
```

it does:

```text
/processed
    ↓
READ ALL JSON FILES
    ↓
LOAD ALL EVENTS INTO MEMORY
    ↓
GROUP ALL EVENTS BY DRIVER
    ↓
ANALYZE ALL EVENTS
    ↓
OVERWRITE /curated/taxi_driver_summary.json
```

The code explicitly reads the processed directory and accumulates all events into `events`. 

Then `analyze_data()` processes those events and groups them by driver. 

So if you have:

```text
processed_events.json
```

containing:

```text
60 events
```

you run the analysis:

```text
60 events → analyzed
```

Later you add another:

```text
60 events
```

and run the same script again, it can analyze the **full contents of the processed data it reads**, rather than only the newly added events.
